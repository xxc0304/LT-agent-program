# 选购服务接入资料清单

用于确定“选购服务更新后，与 OpenClaw 的接入管理”实际要接入哪一个服务，以及如何安全验证。可把本清单转给服务方或项目接口人填写。**不要在此文档、Git、邮件或聊天里填写 API Key、密码、Token、客户真实数据。**凭据仅在确定实现方案后，由用户在本机密钥库/环境变量中配置。

## A. 开始只读接入所需（必填）

| 资料 | 需要填写的内容 | 用途 |
|---|---|---|
| 服务身份 | 官方产品名称、厂商、官方文档/仓库链接；这里的“选购服务”具体是商品搜索、询价、下单，还是别的能力？ | 明确接入对象和第一阶段边界 |
| API 契约 | 官方 OpenAPI 文件或 SDK 仓库/版本；若没有，提供只读查询操作的请求/响应字段说明和错误码 | 实现并验证客户端，不猜接口 |
| 环境地址 | sandbox/test API 的 base URL、适用区域/租户要求 | 只在测试环境验证 |
| 认证说明 | 认证模式、申请流程、需要的权限/scope 名称、过期/刷新/撤销方式；只给说明，不给真实凭据 | 定义最小权限和本机密钥引用 |
| 可用测试方式 | 合成数据 sandbox、测试账号的申请途径、速率限制，以及可复现的成功/失败响应 | 证明连接器兼容，不触碰真实订单 |
| 目标运行环境 | OpenClaw 精确版本、安装方式（npm/git/容器/系统包）、使用的 profile/插件管理方式 | 选择正确的 plugin API 和部署所有者 |

## B. 需要外部写操作时另行填写

若需要创建/修改/取消订单、付款或退款，请逐项填写：

| 项目 | 需要确认的内容 |
|---|---|
| 写操作清单 | 精确到操作名称；不要只写“支持购买” |
| 权限范围 | 每个操作需要的服务端权限/scope，以及最小权限账号如何申请 |
| 用户确认 | 哪些操作必须逐次确认；是否存在不可逆/收费操作 |
| 幂等与状态 | 幂等键规则、超时后查询订单状态的接口、重复提交的语义 |
| 测试约束 | sandbox 是否支持模拟下单/取消；确认不会产生真实扣款或配送 |

在这些项目审查并通过前，连接器只允许只读或纯计划能力；外部写操作默认关闭。

## C. 服务更新与回滚所需

- API/SDK 的版本号、弃用和破坏性变更公告位置、兼容期限。
- 连接器包的发布来源、版本锁定/完整性校验方式和维护责任人。
- 已验证可回滚的连接器版本，以及失败时如何恢复其配置。
- OpenClaw Gateway 更新和 connector 更新是否由不同流程管理；目标机器是否有维护窗口。
- 数据类别、是否保存个人信息、保存位置和保留/删除期限。

## D. 建议先给我的最小资料包

要启动“只读 adapter + Mock/sandbox 合约测试”，先提供 A 中六项；其中 API 契约、认证权限、sandbox 和目标 OpenClaw 版本是硬性前置。真实凭据不用发送给我，等代码就绪后由你在本机安全配置。只读接入完成并通过验收后，再考虑 B 的写操作。

对应的字段格式见 [`openclaw-service-integration.schema.json`](../deployment/openclaw-service-integration.schema.json) 和纯合成示例 [`synthetic-openclaw-service-manifest.fixture.json`](../deployment/fixtures/synthetic-openclaw-service-manifest.fixture.json)。
