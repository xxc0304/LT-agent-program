# Agent 事件触发与家庭记忆 MVP

版本：v0.1（本地实现稿，跨组和老师确认后再冻结）

## 1. Agent 层级与调用边界

```text
用户 / HA 设备状态 / 摄像头视觉结果 / 时钟
                  ↓ 事件适配器（来源仍需逐项接入）
          多 Agent 调度器 / 事件路由层
          ├─ 学习伴学 Agent：识别学习行为，产出 Event
          ├─ 节能 Agent：依据 Event 和设备快照，规划 Task
          ├─ 记忆服务：读取/保存经授权的家庭偏好（横向服务）
          └─ 设备管家 Agent：审批边界、执行设备 Task、回读验证
                              ↓
                     Home Assistant / 设备
```

三个业务 Agent 是按职责协作的同级组件，不是设备管家的“子 Agent”。调度器是控制/路由层；记忆服务是共享数据服务，不负责控制设备。当前代码演示使用进程内 Agent 对象和 Mock HA，不能据此宣称已完成独立 OpenClaw Agent 间的 RPC/消息总线联调。

## 2. 事件触发矩阵

| 事件/输入 | 产生者与入口 | 接收方及触发门槛 | 结果/安全边界 | 当前状态 |
| --- | --- | --- | --- | --- |
| 用户直接查询/控制 | OpenClaw 对话与工具调用 | 设备管家 Skill 选择只读查询、控制、场景或诊断工具 | 控制后回读；开锁需当轮明确确认 | 工具和 Skills 已实现；模型选工具不是固定事件总线 |
| `occupancy_changed` | HA 人体传感器/融合服务适配器 | 调度器按 `consumes` 路由节能 Agent；`occupied=false` 且持续时间达到当前阈值才规划 | 仅对允许的灯、插座、空调生成 Task；设备管家执行 | Agent 规则/Mock 路径可用；真实 HA 事件源待设备组 |
| `home_mode_changed` | 用户模式切换或经确认的定时器 | `mode=away` 时路由节能 Agent；`home`/`sleep` 不触发全屋关机 | 先基于当前设备快照规划，再由设备管家执行 | 规则已实现；真实模式事件源/定时器未接 |
| 学习行为帧/窗口 | 摄像头/本地视觉客户端 | 学习伴学 Agent 识图并产出 `learning_behavior` Event；节能 Agent 仅消费已产生的 Event | 低置信度、待复核、单帧缺少持续性证据不触发控制；原始媒体不跨 Agent | 图片适配器可手动调用；自动采集、时间窗口和摄像头入口未接 |
| `learning_behavior` | 学习伴学 Agent | 除明确目标儿童离位、置信度/持续时间门槛和无需复核外，节能 Agent 还须在当前进程中先实际收到同区域、60 秒内、来自运行时可信白名单的 HA 无人事件 | 只生成节能 Task；课堂整体/单帧/视觉单一来源均不控设备；不能把 `standing`/转身等同于离开；学习事件 payload 自报的佐证不可信 | 本地规则和 Mock 端到端已测；真实来源认证待 HA/传感器联调 |
| `user_device_override` | 用户手动操作/设备事件适配器 | 节能 Agent 记录设备保持期 | 冷却/保持期内不规划反向关机 | Agent API/测试已有；自动捕获真实手动操作尚未接 |
| 设备异常/`diagnostic_alert` | HA 状态适配器或用户查询 | 设备管家运行只读诊断；后续如需通知再路由通知 Agent | 输出 status、证据和建议；不得把诊断说成修复 | 诊断工具已有；真实 HA 事件源待接 |
| `routine_due` | 经单独授权的本地定时器调用作息到期评估器 | 只读取已确认的睡觉/起床偏好；按时区和周内/周末匹配，产生可幂等去重的到期 Event | 记忆不是执行授权；评估器默认关闭，且只返回 Event，不发通知、不控设备；真实调度和通知需另行授权接入 | 到期判定与 Event 草案已实现并有单测；当前无活动定时器/通知通道 |

### 触发处理顺序

1. 适配器接收原始输入，检查来源、时间、房间、隐私级别和事件 ID；原始图片、视频、凭据不得进入标准 Event。
2. 调度器按 Agent manifest 的 `consumes` 订阅关系路由；不匹配则 `NO_ROUTE`。
3. 业务 Agent 执行确定性门槛检查（置信度、持续时间、设备状态、用户覆盖期）；视觉离位还须有本进程已收到的同区域、近期独立 HA 无人事件，不满足则 `NO_ACTION`，并记录原因。
4. 规划 Agent 仅输出 Task；调度器按优先级派发给设备管家；设备管家做权限/策略检查、执行、回读状态并产生回执。
5. 每次输入、Agent 调用、Task 与回执使用同一个 `trace_id` 供追踪。

LLM 可以帮助理解用户的自然语言，但不应单独决定安全阈值、跳过审批或直接执行高风险动作。事件来源和公共字段需与 HA/传感器组确认。

## 3. 家庭记忆的分类和治理

本节描述的是项目中家庭 Agent 的运行时记忆服务，不是 Codex/开发助手对当前用户建立个人记忆，也不是用样本训练 DeepSeek。部署后的数据主体是授权接入该家庭系统的家庭成员；代码测试使用合成 Mock 事件及临时文件，不写入当前用户偏好或真实家庭数据。

### 可保存的 MVP 内容

- 用户明确要求长期采用的舒适温度，例如卧室 `comfort_temperature_c=26`；
- 经授权观察、至少 3 个不同本地日期重复出现且每次置信度达到 0.8 的睡觉/起床时间候选；观察按家庭 IANA 时区归日，并区分周内/周末。当前本地试验暂按最近 15 分钟归并作息时间，作为草案参数待后续标注/样本验证。候选先标记 `pending_confirmation`，只有用户明确确认后才能变为偏好。

### 不应进入长期记忆

- API Key、访问令牌、密码；
- 原始聊天文本、儿童照片/视频、人脸或可识别身份信息；
- 单次指令、一次性设备状态、低置信度推测；
- 设备此刻的灯光/温度状态（需要时应实时向 HA 查询）；
- 不能证明为用户偏好的学习行为标签。学习结果属于受限事件/短期证据，不自动晋升为家庭习惯。

### 记忆记录字段

当前 `PreferenceMemoryStore` 字段包括 `memory_id`、`memory_type`、`value`、`unit`、`subject_id`、`scope`、`status`、`source`、`observation_scope`、`confidence`、`confidence_semantics`、`consent`、`evidence_event_ids`、`evidence_dates`、`observation_count`、`created_at`、`updated_at`、`expires_at`。`confidence` 对推断记忆表示输入观察置信度的跨日平均，`confidence_semantics` 为 `mean_input_observation_confidence`；它不是校准过的偏好概率。用户明确保存的记忆标记为 `explicit_user_assertion`，数值 1 也不代表概率。作息 scope 带 `time_zone` 和周内/周末范围。目前支持 `comfort_temperature_c`、`comfort_brightness_pct`、`sleep_time`、`wake_time` 四类；subject 使用非身份别名（如 `household`），不存姓名。数据结构为 0.6，可迁移 0.1–0.5；0.1/0.2 中缺少可核验证据日期的未确认候选须重新观察，0.3–0.5 数据保留并补充置信度语义。

生命周期：明确持久化请求 → `confirmed`；作息观察或设备操作观察（各自独立授权）→ `observing` → 至少 3 个不同日期但范围内未发现不同值时 `pending_confirmation` → 用户确认后 `confirmed`。同一偏好范围出现不同值时，相关候选进入 `conflict_review`，不会自动晋级；用户看过并选择某个达到证据门槛的候选，或明确保存一个值，才能解决冲突，其他同范围候选会一并清理。候选默认 30 天过期；用户也可删除。`get_household_preference` 不会把 `observing`/`pending_confirmation` 当成可用偏好；若请求范围存在适用的 `conflict_review`，会返回冲突状态及候选值（含仍有效的旧确认值），不回退使用旧值。场景规划、作息预览和到期检查必须停止依赖该偏好的计划/事件，并把冲突信息交给 OpenClaw 询问用户。

### 存储位置

存储后端由 `PreferenceMemoryStore` 提供，OpenClaw 只通过家庭记忆工具访问它，不直接连接数据库。现有安装默认保持 JSON 后端；部署推荐在设备管家插件配置中显式设置 `memoryBackend: "sqlite"`，并可用绝对路径 `memoryDatabasePath` 指定持久化数据库位置。仅在未设置插件级后端时，旧环境变量 `FAMILY_MEMORY_BACKEND` / `FAMILY_MEMORY_DB_PATH` 才作为 SQLite 后端/路径的兼容回退；`FAMILY_MEMORY_PATH` 独立指定 JSON 文件位置。数据库路径必须与显式 SQLite 后端一起配置，且为绝对路径。家庭部署目标为每户一个独立数据库，归属于该家庭边缘网关/家庭平台的数据层；当前不支持一个数据库承载多个家庭，也不会自动向云端同步。

SQLite 实现使用 Node 内置 `node:sqlite`，需 Node.js 22.5+。JSON→SQLite 迁移只能通过 `npm run db:import-json -- <现有记忆.json> [新数据库路径]` 显式执行；目标必须是未初始化的空数据库，源文件保留不动。现有加密备份命令仅适用于 JSON；SQLite 另有 `npm run db:backup -- create/restore` 人工一致性备份/恢复，需 Node.js 22.16+，备份不加密、只写入新路径，不会自动切换 Gateway。

## 4. 当前代码与未接项

- 已有：进程内事件订阅式路由、节能 Agent 的四类事件规则、学习结果 Event 适配器、设备管家执行回读；家庭偏好 JSON/SQLite 存储后端和 12 个 OpenClaw 记忆工具已接入插件源码。SQLite 通过 Gateway 环境变量显式启用，默认仍保留 JSON 以兼容已有部署；数据库目标为每户独立一库，真实 Gateway 尚未部署验收。作息与设备操作观察授权分别默认关闭并持久化；撤回某一授权只清理该范围推断的候选及已确认记忆。候选写入接口不开放给对话模型；设备偏好观察已新增 HA `call_service` 适配路径，仅接受带顶层用户上下文、无父调用的空调温度/灯光亮度设置事件，要求配置家庭时区、登记并核对房间，候选需跨 3 个本地日期并经用户确认。设备数值归纳把温度归一到 0.5°C、亮度归一到 5% 档；只累计归一后的候选值，不保存单次原始设备值。
- 尚未实现/核验：目标 HA 版本中的人工操作、自动化、OpenClaw 控制是否稳定对应预期 `context.user_id` / `parent_id` 尚未真实环境联调；用户 ID不落盘，但该上下文归因不是对所有 HA 集成的绝对保证，未知来源一律过滤。Gateway 重载后是否实际发现和调用新增工具、长时间运行写入是否稳定，也需在本机 profile 下核验。插件源码有效/单测通过不等于 Gateway 工具已运行或真实家庭数据已采集。
- 已新增本地 Mock 例程：结构化 `routine_observation` 经用户授权后转换为本地日期证据，跨 3 个不同日期形成候选；OpenClaw 工具边界传入事件时间而非自行填报日期，运行时代码计算时区日期和 15 分钟时间桶；用户确认后可生成 `routine_due` 的提醒预览。另有空调手动调温与灯光手动调亮两类 Mock 设备学习演示：仅接收合成标记为 `user_manual` 的事件，过滤 automation/agent/unknown，分别累计三天候选、确认后查询偏好；使用临时数据，不接真实 HA、不验证真实来源、不调用 LLM。不会把开关灯擅自推断为睡觉/起床。独立到期评估器可由外部时钟调用并产生稳定 `dedup_key`；默认不开启，且只返回 Event、不发送通知、不执行设备动作。单元测试不创建实际时钟任务。
- 待开发或外部接入：HA 人工/automation/Agent 来源差异的目标版本实测与运行时验收；自动摄像头采集与多帧窗口；周期性调用作息到期评估器的系统时钟触发器；真实日常作息信号适配；由 OpenClaw 对话完成候选主动提示/确认/删除的运行时交互，以及通知渠道和投递回执。睡觉/起床值不能据此自动执行作息设备动作。
- 重要边界：项目代码已具备经授权的家庭偏好候选生成和持久化能力，但不意味着当前已部署的系统会自动观察家庭或已有真实家庭偏好。HA 设备路径须配置家庭自己的授权、HA 用户白名单、时区和已核对设备；Mock 测试使用合成数据。候选须经家庭成员确认才成为偏好；已确认的舒适温度/亮度仅用于对应的预定义场景预览建议（还须校验设备能力与范围），记忆不是执行授权；作息偏好尚未接入自动触发。该机制是基于证据门槛的规则式归纳，不是模型训练。
- 待共同确认：正式事件名称和字段、用户/儿童数据授权与保留期限、定时自动控制的授权规则、记忆是否允许离开家庭边缘端。

### 家庭记忆存储安全与生命周期补充

- **访问权限**：生产目标应保护家庭边缘节点的持久化数据区。当前标准 SQLite/JSON 均没有应用层加密；Windows 部署需核验 Gateway 服务账户和 NTFS ACL，并启用设备/卷加密。不得以单元测试代替系统权限检查。
- **并发**：SQLite 使用数据库事务及 busy timeout 处理跨连接写入；JSON 兼容后端继续使用进程间锁文件。SQLite 仍应由 Gateway 持久化数据区承载，不要放进 Git、CtxHop、普通同步盘、网络共享目录或临时容器层。
- **备份与恢复**：当前加密备份工具只支持 JSON，不支持 SQLite 数据库。SQLite 生产部署前必须补充一致性备份/恢复、备份保留和删除策略；不能把普通文件复制当成已验证的数据库备份。
- **删除**：应用删除只从当前活动数据库/JSON 后端移除指定记忆；不保证文件系统快照或另存备份中的副本被物理擦除。备份副本需遵循同一保留和删除要求，普通日志不得记录被删偏好值。
- **加密边界**：当前后端没有应用层加密。家庭云端副本或跨设备同步尚未实现；若将来需要，须另外设计授权、加密与密钥管理、删除传播和冲突处理。

## 5. 本地验证清单（单元逻辑已覆盖，端到端仍未全部具备）

1. 已有单元测试：用户明确要求记住卧室温度后保存并查询；一次性调温不进入记忆。待通过当前 OpenClaw Gateway 实际对话工具再验一次。
2. 已有 Mock 验证：作息候选在未同意观察时不写入；设备操作观察另需单独授权；设备演示分别验证空调温度和灯光亮度，只统计合成标记的手动操作，过滤自动化、Agent 和未知来源；同一天重复不增加样本；轻微不同的数值先归一到温度 0.5°C/亮度 5% 档，再由三个不同日期形成待确认候选；用户确认后才能查询为偏好。作息确认后可形成 `routine_due` 提醒预览。
3. 已有舒适温度场景预览建议和作息提醒建议；实际时钟触发、对话工具运行时确认、接入真实事件源仍待完成。即使未来形成设备计划，也要重新检查实时状态和策略，记忆本身不能授权执行。
4. 删除、过期及不保存原始内容由存储逻辑测试覆盖；跨进程文件锁有本地测试。生产部署的 NTFS ACL、磁盘加密状态、备份/恢复操作演练、备份删除传播和崩溃残锁人工处置仍需在目标设备验收。
5. 传感器、学习事件有本地路由/不动作测试；HA/MQTT/摄像头和定时事件源的真实接入、完整 Gateway trace 尚未完成。
