# Agent 事件触发与家庭记忆 MVP

版本：v0.1（本地实现稿，跨组和老师确认后再冻结）

## 1. Agent 层级与调用边界

```text
用户 / HA 设备状态 / 摄像头视觉结果 / 时钟
                  ↓ 事件适配器（来源仍需逐项接入）
          多 Agent 调度器 / 事件路由层
          ├─ 学习伴学 Agent：识别学习行为，产出 Event
          ├─ 节能 Agent：依据 Event 和设备快照，规划 Task
          ├─ 记忆服务：读取/保存经授权的家庭偏好（横向服务）
          └─ 设备管家 Agent：审批边界、执行设备 Task、回读验证
                              ↓
                     Home Assistant / 设备
```

三个业务 Agent 是按职责协作的同级组件，不是设备管家的“子 Agent”。调度器是控制/路由层；记忆服务是共享数据服务，不负责控制设备。当前代码演示使用进程内 Agent 对象和 Mock HA，不能据此宣称已完成独立 OpenClaw Agent 间的 RPC/消息总线联调。

## 2. 事件触发矩阵

| 事件/输入 | 产生者与入口 | 接收方及触发门槛 | 结果/安全边界 | 当前状态 |
| --- | --- | --- | --- | --- |
| 用户直接查询/控制 | OpenClaw 对话与工具调用 | 设备管家 Skill 选择只读查询、控制、场景或诊断工具 | 控制后回读；开锁需当轮明确确认 | 工具和 Skills 已实现；模型选工具不是固定事件总线 |
| `occupancy_changed` | HA 人体传感器/融合服务适配器 | 调度器按 `consumes` 路由节能 Agent；`occupied=false` 且持续时间达到当前阈值才规划 | 仅对允许的灯、插座、空调生成 Task；设备管家执行 | Agent 规则/Mock 路径可用；真实 HA 事件源待设备组 |
| `home_mode_changed` | 用户模式切换或经确认的定时器 | `mode=away` 时路由节能 Agent；`home`/`sleep` 不触发全屋关机 | 先基于当前设备快照规划，再由设备管家执行 | 规则已实现；真实模式事件源/定时器未接 |
| 学习行为帧/窗口 | 摄像头/本地视觉客户端 | 学习伴学 Agent 识图并产出 `learning_behavior` Event；节能 Agent 仅消费已产生的 Event | 低置信度、待复核、单帧缺少持续性证据不触发控制；原始媒体不跨 Agent | 图片适配器可手动调用；自动采集、时间窗口和摄像头入口未接 |
| `learning_behavior` | 学习伴学 Agent | 除明确目标儿童离位、置信度/持续时间门槛和无需复核外，节能 Agent 还须在当前进程中先实际收到同区域、60 秒内、来自运行时可信白名单的 HA 无人事件 | 只生成节能 Task；课堂整体/单帧/视觉单一来源均不控设备；不能把 `standing`/转身等同于离开；学习事件 payload 自报的佐证不可信 | 本地规则和 Mock 端到端已测；真实来源认证待 HA/传感器联调 |
| `user_device_override` | 用户手动操作/设备事件适配器 | 节能 Agent 记录设备保持期 | 冷却/保持期内不规划反向关机 | Agent API/测试已有；自动捕获真实手动操作尚未接 |
| 设备异常/`diagnostic_alert` | HA 状态适配器或用户查询 | 设备管家运行只读诊断；后续如需通知再路由通知 Agent | 输出 status、证据和建议；不得把诊断说成修复 | 诊断工具已有；真实 HA 事件源待接 |
| `routine_due` | 经单独授权的本地定时器调用作息到期评估器 | 只读取已确认的睡觉/起床偏好；按时区和周内/周末匹配，产生可幂等去重的到期 Event | 记忆不是执行授权；评估器默认关闭，且只返回 Event，不发通知、不控设备；真实调度和通知需另行授权接入 | 到期判定与 Event 草案已实现并有单测；当前无活动定时器/通知通道 |

### 触发处理顺序

1. 适配器接收原始输入，检查来源、时间、房间、隐私级别和事件 ID；原始图片、视频、凭据不得进入标准 Event。
2. 调度器按 Agent manifest 的 `consumes` 订阅关系路由；不匹配则 `NO_ROUTE`。
3. 业务 Agent 执行确定性门槛检查（置信度、持续时间、设备状态、用户覆盖期）；视觉离位还须有本进程已收到的同区域、近期独立 HA 无人事件，不满足则 `NO_ACTION`，并记录原因。
4. 规划 Agent 仅输出 Task；调度器按优先级派发给设备管家；设备管家做权限/策略检查、执行、回读状态并产生回执。
5. 每次输入、Agent 调用、Task 与回执使用同一个 `trace_id` 供追踪。

LLM 可以帮助理解用户的自然语言，但不应单独决定安全阈值、跳过审批或直接执行高风险动作。事件来源和公共字段需与 HA/传感器组确认。

## 3. 家庭记忆的分类和治理

### 可保存的 MVP 内容

- 用户明确要求长期采用的舒适温度，例如卧室 `comfort_temperature_c=26`；
- 经授权观察、至少 3 个不同本地日期重复出现且每次置信度达到 0.8 的睡觉/起床时间候选；观察按家庭 IANA 时区归日，并区分周内/周末。当前本地试验暂按最近 15 分钟归并作息时间，作为草案参数待后续标注/样本验证。候选先标记 `pending_confirmation`，只有用户明确确认后才能变为偏好。

### 不应进入长期记忆

- API Key、访问令牌、密码；
- 原始聊天文本、儿童照片/视频、人脸或可识别身份信息；
- 单次指令、一次性设备状态、低置信度推测；
- 设备此刻的灯光/温度状态（需要时应实时向 HA 查询）；
- 不能证明为用户偏好的学习行为标签。学习结果属于受限事件/短期证据，不自动晋升为家庭习惯。

### 记忆记录字段

当前 `PreferenceMemoryStore` 字段包括 `memory_id`、`memory_type`、`value`、`unit`、`subject_id`、`scope`、`status`、`source`、`confidence`、`consent`、`evidence_event_ids`、`evidence_dates`、`observation_count`、`created_at`、`updated_at`、`expires_at`。作息 scope 带 `time_zone` 和周内/周末范围。目前仅开放 `comfort_temperature_c`、`sleep_time`、`wake_time` 三类；subject 使用非身份别名（如 `household`），不存姓名。数据结构升级到 0.2；旧版未确认推测保留但不可直接确认，须重新收集不同日期证据。

生命周期：明确持久化请求 → `confirmed`；授权观察 → `observing` → 达到重复门槛后 `pending_confirmation` → 用户确认后 `confirmed`；候选默认 30 天过期；用户可列出、修改（重新明确保存）或删除。未确认候选不能由 `get_household_preference` 读取为可执行偏好。

### 存储位置

默认文件在本机应用数据目录：Windows `%LOCALAPPDATA%\LT-agent-program\family-memory-v0.1.json`；支持用 `FAMILY_MEMORY_PATH` 指定路径。它不属于 Git、普通 OpenClaw Markdown 记忆或跨设备自动同步数据。当前文件是本地 JSON、没有应用层加密；部署前需验证受限文件权限并启用设备磁盘加密。家庭云端复制/跨设备同步必须另行设计加密、授权、删除传播和冲突处理。

## 4. 当前代码与未接项

- 已有：进程内事件订阅式路由、节能 Agent 的四类事件规则、学习结果 Event 适配器、设备管家执行回读；本地偏好存储及 7 个 OpenClaw 记忆工具（含结构化作息观察和只读预览）已接入插件源码，单元测试和插件静态校验通过；作息观察由代码依据带时区的 `occurred_at` 计算家庭本地日期，调用方不能直接伪填观察日期；已确认的舒适温度可进入 `plan_scene` 只读计划建议。
- 尚未核验：当前电脑 OpenClaw Gateway 重载后是否能实际发现并调用这 7 个记忆工具；需在正确的本机 profile 下做运行时检查。插件源码有效/单测通过不等于 Gateway 中工具已可调用。
- 已新增本地 Mock 例程：结构化 `routine_observation` 经用户授权后转换为本地日期证据，跨 3 个不同日期形成候选；OpenClaw 工具边界传入事件时间而非自行填报日期，运行时代码计算时区日期和 15 分钟时间桶；用户确认后可生成 `routine_due` 的提醒预览。另有独立到期评估器，可由外部时钟调用并产生稳定 `dedup_key`；默认不开启，且只返回 Event、不发送通知、不执行设备动作。单元测试不创建实际时钟任务。
- 待开发或外部接入：HA/WebSocket/MQTT 事件源、自动摄像头采集与多帧窗口、周期性调用作息到期评估器的系统时钟触发器、真实日常事件到结构化习惯信号的适配、由 OpenClaw 对话完成“明确记住/展示候选/用户确认/删除”的运行时交互，以及通知渠道和投递回执。睡觉/起床值不能据此自动执行作息设备动作。
- 重要边界：现阶段不是系统自动观察主人并学习习惯。只有显式记忆工具被调用，或上游将满足授权与证据要求的结构化候选交给工具时，才会记录；已确认的舒适温度仅用于场景预览建议，记忆不是执行授权；作息偏好尚未接入自动触发。
- 待共同确认：正式事件名称和字段、用户/儿童数据授权与保留期限、定时自动控制的授权规则、记忆是否允许离开家庭边缘端。

### 本地记忆文件安全与生命周期补充

- **访问权限**：默认写入当前用户的应用数据目录。写入文件和同目录临时锁文件时请求 `0600` 权限；该权限参数在 Windows 上不等价于已核验的 NTFS ACL。部署验收仍需在目标 Windows 设备确认只有预期家庭用户、SYSTEM/管理员等必要主体可访问，并启用设备磁盘加密。不得以本地单测代替 OS 权限检查。
- **单写者**：同一进程实例内串行写；不同进程通过原子创建 `<记忆文件>.lock` 互斥；锁存在时读/写均失败关闭（`MEMORY_STORE_LOCKED`），不尝试自动清锁。异常退出可能留下锁；确认所有相关 Gateway/Node 写入进程已停止后，检查锁文件记录并由用户人工处理。Windows 替换兼容路径还可能留下 `<记忆文件>.<pid>.tmp/.backup` 旁文件，它们可能含旧记忆数据；均按敏感记忆文件保护，相关模式已加入仓库 `.gitignore`。该机制只支持本地文件系统；不要把记忆文件放在网络盘、同步盘或共享路径上。
- **备份与恢复**：MVP 不自动备份或恢复。若要备份，应先取得数据主体/家庭授权，只备份必要文件到加密的本地或离线介质，限制读取权限并记录保留期限；不得放入 Git、普通云盘或 CtxHop。恢复时先备份/保留当前活动文件，将候选恢复文件复制到新路径，校验 JSON 与受支持 schema，再由用户决定切换；当前没有自动恢复命令或冲突合并。
- **删除**：应用删除操作只从当前活动 JSON 中删除指定记忆；过期清理只处理带到期时间的记录。操作不保证 SSD/文件系统快照上的物理擦除，也不会清理用户另存的备份；若存在备份副本，需按同一保留与删除要求处置。生产部署应提供可追踪的删除确认，不记录被删偏好值到普通日志。
- **加密边界**：文件仍是明文 JSON，没有应用层加密。当前方案依赖本机账户 ACL 与全盘加密；如果未来允许跨设备同步或云端副本，必须先单独设计端到端加密、密钥托管/轮换、删除传播和冲突处理，不复用当前 `.lock` 机制。

1. 已有单元测试：用户明确要求记住卧室温度后保存并查询；一次性调温不进入记忆。待通过当前 OpenClaw Gateway 实际对话工具再验一次。

3. 已有舒适温度场景预览建议和作息提醒建议；实际时钟触发、对话工具运行时确认、接入真实事件源仍待完成。即使未来形成设备计划，也要重新检查实时状态和策略，记忆本身不能授权执行。

5. 传感器、学习事件有本地路由/不动作测试；HA/MQTT/摄像头和定时事件源的真实接入、完整 Gateway trace 尚未完成。
