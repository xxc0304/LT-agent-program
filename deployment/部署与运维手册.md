# 部署与运维手册（当前为开发/联调级）

## 1. 支持边界

- 主要目标为 Ubuntu 24.04 LTS + Node.js 24；安装器最低要求 Node.js 20，启用 SQLite 记忆需要 Node.js 22.5 或更新版本。Windows PowerShell 安装器仅作兼容用途。
- Mock 测试和演示默认不依赖真实 HA、家电或模型 API。
- 设备管家 OpenClaw 插件需按团队约定版本部署；当前开发对齐版本为 OpenClaw 2026.7.1-2。目标环境应现场执行 openclaw --version 核实，不能仅凭仓库元数据判断 Gateway 正在运行该版本。
- 当前交付包不是 Linux systemd 服务安装器、Docker 镜像或企业生产部署包。

## 2. 首次部署顺序

1. 在 Ubuntu 上解压代码包到稳定目录；插件会链接到解压目录，部署后不要移动或删除该目录。
2. 核对 Node.js 20+、npm 和 OpenClaw `2026.7.1-2`；启用 SQLite 记忆时，Gateway Node.js 须为 22.5+。
3. 运行 `node deployment/install-agent-stack.mjs` 查看只读计划，确认 CLI 当前指向的 Profile 和主聊天 Agent 正确。
4. 运行 `node deployment/install-agent-stack.mjs --apply`。安装器先检查插件来源、Agent 工作区和权限。若需把会话可见性从 `tree` 调整为 `all`，会检查所有非项目 Agent 是否显式 deny `sessions_list`、`sessions_history`、`sessions_send`、`sessions_spawn`；未能证明隔离时会在备份或配置改动前停止。输入 `INSTALL` 后，才备份配置、安装依赖、链接并启用插件、注册缺少的项目 Agent，再通过 OpenClaw 官方 CLI 合并所需工具和 A2A 设置。
5. 配置完成后，只有明确输入 `RESTART` 才运行 `openclaw gateway restart --safe`；安装器不会默认重启 Gateway。
6. 安装器运行本地/Mock 验证。也可稍后运行 `node deployment/verify-agent-stack.mjs` 或运行相应 Agent 的 Mock 演示。

脚本复用当前 `openclaw` 命令所指向的 Profile，不会安装/升级 OpenClaw、选择模型或写入 API Key。版本不符、Profile 不可读、同名 Agent 工作区冲突或配置校验失败时会停止；不会用 `--force` 覆盖原有插件/工作区。

`tools.sessions.visibility=all` 是 OpenClaw 全局设置；只有所有其他现有 Agent 都明确禁用了会话工具时，安装器才会自动扩大它。Linux 安装器默认只打印计划；Profile 修改前需准确输入 `INSTALL`，所有 JSON 配置写入先通过 `--strict-json --dry-run`。备份保留在原配置文件旁；失败时不会尝试自动恢复插件、Agent 或配置的部分副作用。

Windows 兼容入口仍拒绝以 `.cmd`/`.bat` 作为 OpenClaw CLI 入口，因为这类 shim 可能破坏 `--strict-json` 参数中的引号。请用 `Get-Command openclaw -All` 查找 `.ps1` 或 `.exe` 入口，必要时用 `-OpenClawPath` 明确指定。

## 3. 家庭记忆数据库

安装器默认保留现有后端。需要把家庭记忆保存在 OpenClaw 所在的边缘网关 SQLite 数据库时，在 Linux 包根目录运行：

```bash
node deployment/install-agent-stack.mjs --apply --enable-sqlite-memory
```

安装器会把 `memoryBackend=sqlite` 和数据库路径写入活动 Profile 的 `plugins.entries.device-manager.config`。首次启用的默认路径为活动 `openclaw.json` 同目录下的 `device-manager/family-memory.sqlite`。如需使用其他持久化数据区，可指定一个**绝对路径**：

```bash
node deployment/install-agent-stack.mjs --apply --enable-sqlite-memory --memory-database-path "/var/lib/openclaw/family-memory.sqlite"
```

自定义数据库路径必须在解压后的代码包目录之外，避免下一次打包时把家庭数据带入交付包。若 Profile 已经配置 SQLite，之后不带 `-MemoryDatabasePath` 重跑安装器会保留现有数据库路径；若使用的是隐式运行时默认路径，也不会改写成另一个路径。只有明确提供新的绝对路径时才会切换数据库位置。安装器会先展示部署计划，并询问是否安全重启 Gateway；只有明确回答同意才会重启。

OpenClaw Gateway 实际运行的 Node.js 必须为 22.5 或更高版本；安装器会检查当前命令行 PATH 中的 Node，但若 Gateway 服务由其他运行时启动，还需由部署管理员核实服务实际使用的版本。不启用 SQLite 时仍支持 Node.js 20+。安装器不复制、删除或自动迁移原 JSON 记忆，也不创建真实家庭记忆。旧数据如需保留，须先按 `agent-memory/README.md` 的显式导入流程导入到目标数据库。插件在 Gateway 加载时创建数据库目录并打开库，首次初始化 SQLite 表；数据库应放在本机持久化磁盘，不要放入 Git、普通网盘或网络共享目录。当前实现没有应用层加密，部署方仍需按目标设备的账户 ACL 和磁盘保护要求配置数据目录。

不带 `-EnableSQLiteMemory` 的安装会保留 Profile 中已有的插件配置；因此从 SQLite 回退时，应由 Profile 管理员显式调整后端并保留数据库文件，不能把切换后端当作删除数据。

## 4. 设备后端选择

设备管家后端默认为 Mock。真实 HA 模式读取以下进程环境变量：

- DEVICE_MANAGER_BACKEND：home-assistant
- HA_URL：Home Assistant 的 HTTP(S) 地址
- HA_TOKEN：Home Assistant 长期访问令牌
- HA_ENTITY_ALLOWLIST：可选的实体 ID 允许列表，逗号分隔，建议配置为最小范围
- HA_CONFIRMATION_REQUIRED_ENTITIES：需额外确认的实体 ID，逗号分隔
- HA_REGISTRY_ENRICHMENT：默认尝试 WebSocket Registry；环境不支持时可显式设 false，退化为 REST-only 并在结果中标明

真实后端不得只改一行配置就直接开放全部写操作。先由设备所有者核实实体、房间、能力和允许动作，配置最小实体范围与确认策略，再启动 Gateway 并做只读检查。

### 门锁解锁的独立认证

门锁解锁除聊天中的审批外，还需要独立可信认证服务签发一次性短时授权。设备管家只负责向认证服务提交审批 ID、计划 ID、计划指纹、门锁实体 ID 和 `unlock` 动作；认证服务应在自己的可信界面中完成人员认证，并返回 Ed25519 签名授权。PIN、生物识别数据和签名私钥必须留在认证服务及其可信界面中，不通过聊天、OpenClaw 工具参数或设备管家传递。

Gateway 侧可配置以下进程环境变量：

- `DEVICE_MANAGER_LOCK_AUTH_URL`：认证服务 HTTPS 接口。仅本机回环地址允许使用 HTTP。
- `DEVICE_MANAGER_LOCK_AUTH_PUBLIC_KEY`：用于验证签名的 Ed25519 公钥（PEM）；只能放公钥，不能放签名私钥。
- `DEVICE_MANAGER_LOCK_AUTH_ISSUER`：授权声明中的签发方标识；配置公钥时必填。
- `DEVICE_MANAGER_LOCK_AUTH_AUDIENCE`：授权接收方标识；可选，默认 `lt-agent-device-manager`。

认证服务接收 POST JSON，字段为 `approval_id`、`plan_id`、`plan_fingerprint`、`device_id`、`action` 和 `expires_at`，成功时返回 `{ "proof": "<signed-assertion>" }`。签名声明需包含 `iss`、`aud`、`sub`、唯一 `jti`、`iat`、`exp`，并原样绑定上述审批、计划、设备和动作字段；签名算法为 Ed25519（JOSE `EdDSA`），授权有效期最多 60 秒。Gateway 会校验签名、签发方、受众、时效、授权范围和重放，并在真实 HA 写入前再次执行门禁。

未配置认证服务或公钥、认证失败、授权过期/重放/范围不符时，系统会拒绝解锁。当前代码提供认证服务适配和授权校验，不包含认证 UI、PIN 服务或私钥签发服务；这些需要由部署方提供并在可信边缘环境单独部署。密钥应通过目标环境认可的服务级密钥注入方式配置，不能写入仓库、部署包或命令行参数。安装器的本地 Mock 验证会清除 HA 与门锁认证服务变量，避免验证阶段联系外部服务。

Linux 可在当前 Shell 中交互读取令牌后导出，仅供本次进程使用：

```bash
read -rsp "HA Token: " HA_TOKEN; echo
export HA_TOKEN
export HA_URL="http://HA主机地址:8123"
export DEVICE_MANAGER_BACKEND="home-assistant"
```

完成后可运行 `unset HA_TOKEN HA_URL DEVICE_MANAGER_BACKEND`。如果 Gateway 由 systemd 服务启动，当前终端的变量不会自动传给服务；应使用管理员批准的本机密钥管理方式安全注入，并以 Gateway 实际运行用户验收。

Windows PowerShell 兼容入口下，开发者可用安全提示输入令牌：

    $secureToken = Read-Host "输入 HA Token（不会回显）" -AsSecureString
    $tokenPointer = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($secureToken)
    try {
        $env:HA_TOKEN = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($tokenPointer)
    } finally {
        [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($tokenPointer)
    }
    $env:HA_URL = "http://HA主机地址:8123"
    $env:DEVICE_MANAGER_BACKEND = "home-assistant"

PowerShell 变量仅对当前进程及其子进程有效。无论 Linux 或 Windows，都不要把令牌放入脚本、仓库、全局明文环境变量或聊天。

## 5. 设备上线流程

1. 先由 HA 集成接入设备；本项目不会扫描局域网或自行配网。
2. 运行只读设备发现，核对实体 ID、物理设备分组、房间和动作能力。
3. 新发现设备默认为待核对，不应直接纳入节能控制。
4. 设备所有者批准设备、房间和节能授权范围；门锁、阀门、高功率或其他高风险设备单独定义确认策略。
5. 对每种目标动作先验证服务返回，再回读设备状态；失败、超时和状态不一致均按未成功处理。

## 6. 常见故障处理

| 现象 | 先检查 | 安全处理 |
|---|---|---|
| 插件未加载或工具不可见 | OpenClaw 版本、plugin validate、runtime inspect、Gateway 是否重载 | 不扩大工具 allowlist；修复版本/插件路径后重新检查 |
| HA 连通性失败 | Gateway 运行环境中的 HA_URL、令牌有效期、网络/TLS | 不把令牌发到聊天；回退 Mock，不重复写操作 |
| 实体不存在或未批准 | HA 实体清单、设备登记/房间审核 | 重新只读发现并由设备所有者核对，不猜测替代实体 |
| 事件来源不可信或信息冲突 | source 身份认证、事件时效、区域和当前状态 | 暂停受影响动作，询问/反馈；无人应答则不执行待确认写操作 |
| 控制调用超时或回读不一致 | 重新读取当前状态和设备诊断 | 不自动重放；查明状态后由用户/策略重新评估 |
| 记忆或提醒存储故障 | 目标文件 ACL、锁诊断、磁盘可用空间 | 保留原文件，按人工运维流程处理，不自动删锁或重建数据 |
| SQLite 记忆插件未启动 | Node.js 是否为 22.5+、插件配置的后端/绝对路径、Gateway 加载日志 | 不删除原数据库；修正配置后由 Profile 管理员安排 Gateway 重载 |

## 7. 停用与回退

演示只运行短进程，关闭进程即可结束。OpenClaw 部署回退应通过目标环境的官方插件 disable/uninstall 流程操作；安装时创建的 `.pre-lt-agent-program-*.bak` 配置备份保留在原处。脚本不会自动回滚或删除 Profile、插件工作区及备份；由 Profile 所有人核对后再决定如何恢复。

回到 Mock 时，在新启动的进程环境中使用 DEVICE_MANAGER_BACKEND=mock；再次运行本地集成验证。真实 HA 令牌和配置应按部署方安全流程撤销或轮换，不通过删除项目目录代替凭据撤销。

## 8. 企业部署前的运维验收

至少完成：目标机器 ACL/磁盘加密检查、密钥轮换演练、Gateway 重启/升级/回滚、HA WebSocket 断线重连、HA 不可用、实体删除/改名、设备服务成功但状态不变、事件重复/延迟/伪造、审批超时和人工澄清、存储损坏与备份恢复、日志脱敏和保留策略验证。当前 Mock/单元测试不能替代这些现场验收。
