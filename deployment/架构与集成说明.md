# Agent 代码架构与集成说明

## 1. 交付目标

这套代码把“接收任务、业务分析、任务调度、设备控制、结果核验”拆成边界明确的模块。当前可交付的重点是**本地可验证的集成骨架和 Mock 闭环**；真实家庭数据和家电控制需要另行配置、授权并验收。

## 2. 组件分工

| 组件 | 代码目录 | 主要职责 | 不负责什么 |
|---|---|---|---|
| OpenClaw 运行平台 | 目标电脑本机安装与 profile；仓库含设备管家插件 | 提供对话入口、工具运行时和 Agent 工作区；可使用已配置的模型理解口语并组织反馈 | 仓库不包含目标电脑的 Gateway 状态、模型凭据或 profile |
| 多 Agent 编排器 | multi-agent-orchestrator | 提供两种层次：原有进程内事件调度器；新增平台级 OpenClaw 计划调度器，按登记能力调用一个或多个 Agent、检查依赖/冲突并返回追问状态 | 不直接连接 HA；新平台插件需安装到目标 Gateway 才会成为实际对话入口 |
| 能源管家| energy-saving | 分析可信、有效的家庭状态事件，按策略提出节能 Task | 不直接访问 HA，不直接控制设备；当前主要是确定性策略，不等于模型自主推理 |
| 设备管家 Agent | device-manager | 清单和能力校验、安全策略、确认/澄清、控制执行、状态回读和事件记录 | 不能从未知数据中猜实体、房间或动作 |
| 公共契约 | common-contracts | 定义 Agent 间交换的对象、字段、枚举和样例 | v0.1 当前是本组草案，不是跨组最终冻结版 |
| 家庭记忆 | agent-memory | 可选地存放经授权的结构化偏好/候选，支持确认、撤回和删除 | 不保存全部聊天原文；记忆本身不是操作授权 |
| Home Assistant 适配 | device-manager/src/mock-ha.js、real-ha.js 等 | Mock 与 HA 后端采用相同工具结果形状；真实模式经 HA API 读取/控制 | 真实适配器存在不代表已通过真实家庭设备验收 |

## 3. 主调用链

    用户口语
        → OpenClaw 主对话模型理解需求并提出多步 Agent 计划
        → orchestrate_household_agents 平台入口
        → 校验 Agent/能力登记、依赖关系和互斥设备动作
        → 调用一个或多个已登记 Agent（独立分析可并行）
        → 需要设备任务时，由设备管家检查设备、授权和确认策略
        → Mock HA 或真实 HA 执行动作（仅设备管家可执行）
        → 汇总 Agent 结果、状态回读或澄清问题
        → OpenClaw 主对话答复用户；用户回复后生成新计划

自然语言理解与设备执行分开：OpenClaw 已配置的模型负责理解和提出计划；平台代码校验目标 Agent、能力、依赖和冲突，不能因模型计划就授予设备权限。能源管家当前主要执行确定性策略；它生成的是候选建议/任务，不是设备授权。确认、危险、冲突或不确定结果会回到 OpenClaw 主对话，等待用户补充或确认，不会被静默跳过。

用户面向的目标入口是 OpenClaw `dev` 主 Agent；新平台插件提供 `orchestrate_household_agents`，按计划通过 Gateway 调用独立的 `learning-companion`、`energy-saving`、`device-manager` 及后续登记 Agent。设备管家仍使用自己的设备清单、计划、安全策略、确认、执行和状态回读工具。旧 `talk_to_device_manager` 保留为兼容工具，但部署器会在主 Agent 上显式禁用它，以免绕过平台调度。平台层代码和既有 `MultiAgentScheduler` 进程内事件队列属于不同调用路径。

## 4. 不可信或矛盾信息如何处理

1. 检查事件结构、时间有效性、来源可信边界和目标是否清楚。
2. 证据不足、事件互相矛盾、目标有多种解释时，阻止受影响的自动设备动作；返回澄清/挑战结果，而不是把整项业务悄悄丢弃。
3. 平台调度器将 Agent 的问题/冲突/确认状态和可读选项返回 OpenClaw；主对话用自然语言询问用户。收到答复后由 OpenClaw 重新理解并提交新计划。当前 MVP 不持久化待答计划。
4. 无人应答时，待确认写操作过期不执行；无关且安全的只读处理可继续。具体是延迟、取消还是安全兜底，由设备风险策略决定。
5. 执行超时或状态回读不确定时，不自动重放可能产生重复影响的命令；先查询当前设备状态并反馈。

对于公开对话工具提交的事件，事件里的 source_agent 字段本身不是身份认证。真实 HA 自动事件需要可信的接入适配器提供认证边界；没有这个适配器时，不得把普通对话输入伪装成可信传感器事实。

## 5. 可复现的集成示例

    occupancy_changed 事件（客厅无人 10 分钟）
        → 能源管家生成两条设备任务
        → 调度器将任务交给 device-manager
        → Mock HA 关闭客厅灯和插座
        → 逐项读取最终状态并输出 SUCCEEDED 回执

运行命令：

    .\deployment\Run-Agent-Integration-Demo.ps1

该演示用合成事件与独立 Mock 后端；不调用 DeepSeek、不启动 OpenClaw Gateway、不连接真实 HA，也不控制物理设备。

## 6. 当前集成边界

- OpenClaw 的模型/API 配置在各部署机器本地，不属于项目源代码。
- 主编排器当前是单进程内存实现；Gateway 重启后队列和 trace 不作为持久队列继续运行。
- 当前仓库没有真实 HA 传感器事件推送到编排器的生产级、来源认证适配器。
- real-ha.js 有 HA API 适配代码及 Fake HA 自动化测试；不同 HA 集成、实体能力和房间映射仍需现场确认。
- 内部 OpenClaw profile 中 Agent 已注册或插件校验通过，不等于本交付包在目标机器上的 Gateway 已加载并端到端工作。
- Memory、提醒和设备清单等本地存储要按目标家庭 ACL、备份、保留和删除策略单独验收。
