# Agent 组接口联调指南

## 1. 联调目标

让设备/感知组、平台组和 Agent 组先使用同一份结构化消息完成 Mock 联调，再将来源认证、真实协议和设备映射替换为现场实现。公共契约 v0.1 是本组的讨论稿，接口字段和枚举须由相关小组共同确认后才能冻结。

## 2. 主要对象

公共 Schema 位于 common-contracts/schemas，合法和非法样例位于 common-contracts/examples。

- Event：设备状态、占用或其他感知事实。至少需要 schema_version、event_id、event_type、occurred_at、payload 等契约字段。
- Task：Agent 请求目标 Agent 执行的结构化任务。设备动作使用 device_action、target_ref、action、parameters、priority、deadline_ms、resource_requirement、privacy_level、data_level、idempotency_key 和 trace_id 等字段。
- TaskReceipt：执行后的状态，例如 SUCCEEDED、FAILED、DENIED、CHALLENGE、TIMEOUT 或 RETRYABLE。
- PolicyDecision：允许、拒绝、需确认或需澄清的策略结果；生产环境的审批身份和答复通道仍需宿主系统提供。

字段以当前 Schema 和示例为准，不能只照本页手工复制。兼容字段会在边界处规范化；同一对象中的旧字段和新字段若互相冲突，应拒绝而不是猜测。

## 3. 对接时各组需提供的信息

| 提供方 | 必须提供 | 为什么需要 |
|---|---|---|
| 传感器/设备接入组 | 事件类型、时间戳含义、区域 ID、状态/置信度、来源身份如何认证、事件是否可能重复或延迟 | 判断事件是否新鲜、可信，避免伪造或过期事件触发设备动作 |
| HA/设备组 | HA 版本、实体 ID、域、房间映射、可用性、支持能力、状态读取/写入方式、测试实体 | 设备管家据此发现设备并校验动作，不凭设备名称猜测能力 |
| 编排/平台组 | Agent 注册方式、目标 Agent 名称、任务超时、确认结果的回传接口、trace 查询方式 | 让事件能正确路由、挑战能回到用户、故障能追踪 |
| 项目共同维护者 | 契约版本、优先级/数据级别语义、字段变更流程和兼容期限 | 防止不同小组各自修改后互相不兼容 |

不要在 Git、普通文档或聊天中交换 HA Token、模型 Key 或家庭成员标识。凭据应通过部署方批准的密钥管理方式交付。

## 4. 集成前检查清单

- 所有事件的 event_id 唯一且稳定，重试时使用同一幂等身份。
- occurred_at 表示事件实际发生/确认时间，时间标准一致；不要用消息重放时间冒充发生时间。
- area/room 使用协商好的稳定 ID，不把“客厅”“living room”等自由文本当作认证或唯一标识。
- source_agent 字段只标识声明来源；生产可信度必须由接入层认证，不能由请求方自己填字符串取得。
- 事件缺少来源认证、区域或关键证据时，进入澄清/等待/拒绝策略，不自动执行有影响的设备动作。
- Task 的 target_agent、priority、privacy/data level 和执行模式语义由各组共同确认。
- 设备管家执行后返回逐设备结果；不能仅凭 HA 服务调用 HTTP 成功推断设备状态已改变。
- 确认/澄清是异步交互：用户答复需关联原任务并再次校验当前设备状态，不能用旧批准执行已变化的计划。

## 5. 推荐联调顺序

1. 先运行公共契约样例校验：

       node common-contracts/validate-examples.mjs

2. 双方各自用样例构造 Event / Task，并跑契约校验；失败时先对字段、枚举和版本达成一致。
3. 用 Mock HA 走一次占用事件 → 节能 Task → 设备管家执行 → TaskReceipt 的完整闭环：

       .\deployment\Run-Agent-Integration-Demo.ps1

4. 用对方提供的测试事件替换合成 Event，检查缺字段、过期、重复、互相矛盾和来源不可信场景。
5. 先只读连接真实 HA，核对实体/房间/能力；再在批准的测试设备上验证低风险写入和回读。
6. 由设备所有者批准确认策略、事件白名单和回滚方案后，才进行跨组联调验收。

## 6. 契约定稿事项

至少需要一起确认 source_agent / target_agent 的正式命名、Task 类型、优先级、deadline 单位、隐私级别、数据级别、资源需求、CHALLENGE/澄清回传结构、Event 来源认证、设备统一模型映射和版本兼容策略。未确认前仍以 v0.1 草案标注，不向企业宣称是最终标准。
