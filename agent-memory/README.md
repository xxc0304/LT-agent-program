# 家庭偏好记忆 MVP

`src/memory-store.js` 提供家庭运行时记忆 API，当前支持舒适温度、灯光亮度、睡觉时间和起床时间。数据结构版本为 0.6，可读取 0.1–0.5；0.1/0.2 中缺少可核验证据日期的未确认候选会标记为需重新观察，0.3–0.5 的数据会保留并补充置信度语义。它不是向量知识库，也不保存原始对话、设备瞬时状态、儿童图片/视频、API Key 或密码。

这里实现的是**项目中家庭 Agent 的运行时记忆与偏好学习能力**，不是 Codex/开发助手对当前用户建立个人记忆，也不是用这些样本训练 DeepSeek。部署到家庭后，只有家庭成员明确授权、可信事件满足来源和重复证据门槛，系统才生成待确认的家庭偏好；确认后保存在家庭边缘端，并可用于后续场景建议。本仓库验证使用合成 Mock 事件和临时文件，不会写入当前用户的个人偏好或真实家庭数据。

## 当前实现

- 用户明确要求长期记住并授权后，可保存已确认偏好；相同对象/房间/日期范围的新值会覆盖旧值。
- 作息观察授权、设备操作观察授权与作息提醒授权相互独立，且默认全部关闭。只有对应范围的用户明确授权后，可信结构化事件才可进入候选；至少 3 个不同本地日期、每条观察置信度不低于 0.8，才形成 `pending_confirmation`。同一偏好范围内观察到不同值时，相关候选转为 `conflict_review`，阻止其自动进入待确认状态；只有用户看过候选并明确选定，或显式保存一个偏好值，才能解决冲突。`confidence` 是已接收观察置信度的平均值，不是“偏好成立概率”或模型准确率；`confidence_semantics` 会标明该语义。当前 HA 设备操作观察器使用固定 0.9 作为直接登录用户服务调用的来源门槛参数，并非由真实家庭数据校准；Mock 同样不代表真实识别准确率。跨日重复、值归一化、冲突阻断和用户确认才是当前候选推断的主要约束，不能把这个数字宣传成概率。设备操作推断会把温度归一到 0.5°C、亮度归一到 5% 档后再累计相近设置；原始设备事件值不会写入记忆，候选仍需用户确认。作息值关联家庭 IANA 时区并按周内/周末区分；观察时间按最近 15 分钟归并，需在用户确认时说明为近似值。用户撤回某一范围的授权时只删除该范围的推断候选和已确认推断记忆，用户明确要求保存的偏好不受影响。`getPreference()` 不会把待确认候选当成偏好；若存在适用的 `conflict_review`，则返回带候选值的冲突结果而非旧确认值，调用方必须阻止依赖该偏好的计划并请用户选择。提醒授权只允许后续调度运行器使用已确认作息；授权本身不采集作息，也不会启动定时器。
- 支持查询（精确房间/日期范围优先，随后回退到通用偏好）、列出、删除和过期清理。
- JSON 兼容后端仍是默认值，以免旧安装在更新后切换到空数据库。OpenClaw 部署优先在设备管家插件配置中设置 `memoryBackend: "sqlite"` 和可选的绝对路径 `memoryDatabasePath`；交付包安装器可用 `-EnableSQLiteMemory` 显式启用，默认路径为活动 OpenClaw 配置文件旁的 `device-manager/family-memory.sqlite`。没有插件级设置时仍支持旧的 `FAMILY_MEMORY_BACKEND=sqlite` / `FAMILY_MEMORY_DB_PATH` 环境变量；插件级设置优先于环境变量。未配置数据库路径时，代码优先使用 `OPENCLAW_STATE_DIR/device-manager/family-memory.sqlite`，否则使用系统应用数据目录。家庭部署建议每户一个数据库并把它放在 Gateway/边缘节点的持久化状态区；该初版不支持一个数据库承载多个家庭。
- SQLite 后端使用 Node 内置 `node:sqlite`，该后端需要 Node.js 22.5 或更高版本；不需额外安装数据库服务或第三方包。数据按记忆行和元数据表持久化，通过事务处理更新，OpenClaw 工具仍调用同一 `PreferenceMemoryStore` API。现有记忆 JSON 不会自动迁移；需显式导入：`npm run db:import-json -- <现有记忆.json> [新 SQLite 数据库路径]`。导入只允许写入未初始化的空数据库，源 JSON 不会被删除或修改。
- 标准 SQLite 数据库和 JSON 文件都没有应用层加密。Linux/macOS 创建的数据库文件限制为当前用户权限；Windows 仍需在目标 Gateway 上核验 ACL，并保护持久化数据区。SQLite 的一致性事务和锁由数据库负责；不要把数据库放进 Git、CtxHop、普通网盘或网络共享目录。
- 现有 `backup` 命令加密备份的是 JSON 文件，不应拿它备份 SQLite 数据库。SQLite 现已提供人工触发的一致性备份/恢复命令：`npm run db:backup -- create <当前记忆.sqlite> <新建备份.sqlite>` 和 `npm run db:backup -- restore <备份.sqlite> <新建恢复库.sqlite>`；仅创建新文件，不覆盖，不改动 Gateway 当前配置。该命令需要 Node.js 22.16+，且产生的 SQLite 文件未加密；自动备份/保留轮转与密钥管理仍未实现。操作说明见 [`../docs/household-memory-sqlite-backup-v0.1.md`](../docs/household-memory-sqlite-backup-v0.1.md)。
- 新增显式调用的加密备份/恢复库 `src/encrypted-backup.js` 与终端入口 `src/backup-cli.js`：使用 scrypt 派生密钥和 AES-256-GCM 完整性认证；创建备份时持有源文件锁，恢复先验证认证与记忆 JSON/schema；备份和恢复目标均使用“仅新建”策略，不覆盖已有文件。命令是 `npm run backup -- create <家庭记忆.json> <新建备份.enc.json>` 和 `npm run backup -- restore <备份.enc.json> <新建恢复文件.json>`；口令只在交互终端隐藏输入，创建时需输入两次，至少 12 UTF-8 字节，不通过参数、环境变量或管道读取，也不记录或保存。尚未对真实家庭记忆执行备份或恢复。还原后的活动文件仍是明文 JSON，必须由 NTFS ACL/磁盘加密保护；备份介质应是受限的本地/离线介质，不能放普通云盘、Git 或 CtxHop。加密备份也不替代独立的口令安全保管。
- 新增 `src/routine-trigger.js`：外部本地调度器可按时区轮询已确认的睡觉/起床偏好，在默认 1 分钟窗口内生成稳定的 `routine_due` Event 和 `dedup_key`；同一偏好、同一本地日期的重试会生成相同事件。它默认 `scheduleAuthorized: false`；即使单独授权启用，也只返回事件，不建系统定时器、不发送通知、不控制设备，实际通知通道仍由经授权的外部调度/通知适配器负责。
- 新增 `src/routine-runner.js`：提供默认关闭、需可信本地运行开关和持久化用户授权后才能启动的进程内周期轮询器，连接到期评估器与调用方注入的事件/通知接收器；进程内按 `dedup_key` 去重，失败可重试，并将稳定幂等键传给接收器。撤回提醒授权后，运行器在下一次检查时会停止；它不自动启动，不访问默认家庭记忆路径，不直接发送通知或控制设备。跨进程持久化去重由接收器负责。细节见 [`ROUTINE_RUNNER.md`](ROUTINE_RUNNER.md)。
- 新增 `src/home-assistant-device-action-observer.js`，并接入 HA WebSocket 监测器：当用户明确开启独立的设备操作观察授权、明确启动设备监测、配置 `HOUSEHOLD_TIME_ZONE` 和 `HOUSEHOLD_HA_OBSERVATION_USER_IDS`，且设备清单已批准设备和房间后，监测器才会额外订阅 `call_service`。用户 ID 白名单只列家庭成员的 HA 用户 ID，不得包含设备管家所用的服务账号；未配置白名单时只订阅普通状态监测，不采集服务调用。适配器只把白名单用户顶层上下文（无父调用）中的 `climate.set_temperature`、带亮度参数的 `light.turn_on` 归一为候选；automation/agent 子调用、未核对房间和其他动作均忽略。候选至少跨 3 个家庭本地日期后仍需用户确认，不能直接控制设备。用户 ID/原始服务数据不保存；上下文 ID 与实体 ID 经 SHA-256 混合后仅作为去重证据 ID，记忆仅存偏好值、房间、日期及候选状态。撤回授权会立即取消 `call_service` 订阅。
- 删除会从活动记忆文件移除记录，不等同于对 SSD、文件系统快照或用户另行保存的备份进行安全擦除；如果曾建立备份，应按相同保留/删除策略处置备份副本。

## 暂不保存

不保存原始聊天文本、原始图片/视频、儿童身份信息、每分钟设备状态、凭据，或只有一次/低置信度的行为推断。过期推测候选默认 30 天清理；已确认偏好可设置过期时间，也可由用户随时删除。

## 运行测试

```powershell
Set-Location agent-memory
npm test
npm run demo
```

当前通过 OpenClaw 插件暴露 12 个记忆工具（查询、列出、显式保存、作息与设备操作观察授权查询/修改、独立作息提醒授权查询/修改、候选确认、作息预览、删除）。观察候选写入仍只开放给内部可信事件适配器，不提供给对话模型，避免模型伪造事件 ID、日期或置信度。已确认的舒适温度可进入 `plan_scene` 只读个性化建议。作息到期评估器和可选周期运行器已实现，但没有在 OpenClaw/Gateway 或系统启动时自动启用，也没有通知发送器；未显式记录用户提醒授权时，运行器也会失败关闭。

设备管家插件在服务启动/停止时打开/关闭数据库连接。推荐部署通过 OpenClaw 插件配置选择后端，环境变量仅用于兼容旧安装；工具名称和工具入参不因存储后端改变。当前测试覆盖了插件级 SQLite 配置、旧环境变量回退、配置优先级、工具写入/重新打开后读取以及服务停止时关闭连接；这不等于已在老师的统一 Gateway 部署验收。启用 SQLite 不会自动迁移已存在的 JSON 数据。

新增的 Mock 学习演示模拟空调手动调温和灯光手动调亮两类事件；使用临时记忆文件，演示后删除，不连接真实 HA、不验证真实来源、不调用 LLM，也不代表真实用户行为识别。现已实现真实 HA WebSocket `call_service` 事件的候选适配路径，但真实家庭验证仍未完成：需要确认目标 HA 版本在手动操作、自动化、OpenClaw 控制等情况下的 `context.user_id` / `parent_id` 表现；由家庭管理员仅将家人账号加入 `HOUSEHOLD_HA_OBSERVATION_USER_IDS`，排除 OpenClaw 服务账号；配置家庭时区，完成设备和房间核对，并做 Gateway 重启后持续写入验证。未配置用户白名单时，监测器不订阅 `call_service`。某些 HA 前端/集成可能缺少上下文或产生不同调用链；本实现选择忽略未知来源，不能声称所有手动操作都能学习。该路径只观察直接、白名单用户服务调用，不从 `state_changed` 推断操作来源。作息时间按最近 15 分钟归并；到期事件评估只产出幂等 `routine_due` Event，不启动定时器、不发送通知、不控制设备。Gateway 重载后实际调用这些工具的运行时核验也应单独完成，不能用插件静态校验代替。

运行 Mock 设备行为学习演示：

```powershell
Set-Location device-manager
npm run demo:mock-memory-learning
```

同一演示也注册为 OpenClaw 插件工具 `run_mock_household_memory_learning_demo`，仅在家庭成员明确要求演示时调用。它与正式记忆读写工具隔离，使用专用 Mock 和临时目录；Gateway 需重新加载插件后才会显示该工具。插件 SDK 级的候选查看、确认、删除拒绝和撤回授权流程由 `test/openclaw-memory-runtime.test.js` 验证；当前运行环境尚未完成新的 Gateway 端到端调用验收。

设备行为学习需由家庭成员在当前 OpenClaw 对话中显式开启 `set_household_device_action_observation_consent`，配置进程环境变量 `HOUSEHOLD_TIME_ZONE`（例如 `Asia/Shanghai`）和仅含家人账号的 `HOUSEHOLD_HA_OBSERVATION_USER_IDS`，先启动只读设备监测，并通过设备发现/登记核对目标设备的房间。不要将设备管家 HA 服务账号放进学习白名单。撤回该类授权会取消服务事件订阅并清理由设备操作推断的候选及已确认记忆，不影响用户明确保存的偏好和作息观察数据。

部署前仍需在目标设备核验本地文件 ACL/磁盘加密，并确定经授权的备份/恢复流程、家庭成员范围，以及是否允许跨设备同步。活动家庭记忆文件仍无应用层加密；禁止把家庭记忆文件提交 Git、放进普通云盘或 CtxHop。加密备份库仅在临时测试数据上验证，实际数据的备份/恢复须另行获授权并先选定受控目标。
