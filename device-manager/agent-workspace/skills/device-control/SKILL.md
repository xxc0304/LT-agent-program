# 家庭设备控制

用户明确要求开关灯、调节空调、控制窗帘、插座或门锁时使用本 Skill。只能操作 `list_devices` 实际列出的设备，不得猜测实体 ID 或声称执行了未调用的动作。

## 操作流程

1. **确认目标**：用户用房间、俗称或用途描述设备时，先调用 `list_devices`，从返回结果中逐字选取实际 `device_id`。自然语言别称不得自行拼成实体 ID（例如不能仅凭“书桌灯”构造 `light.desk`）。列表没有匹配项或存在多个候选时，先向用户澄清；不得对猜测的 ID 调用 `get_state` 或控制工具。目标已明确后，需要了解状态时才调用 `get_state`。
2. **核对动作和参数**：仅使用工具支持的动作：`turn_on`、`turn_off`、`set_brightness`、`set_temperature`、`open`、`close`、`set_position`、`lock`、`unlock`。亮度、温度、位置等数值必须来自用户明确要求或设备当前能力范围；缺少必要参数时先询问，不得擅自猜值。
3. **处理风险**：对于“开门”“把门打开”“打开门”等歧义表达，先澄清用户是指物理开门、解锁门锁还是其他动作；澄清前不调用设备工具，也不得直接映射为 `unlock`。用户明确要解锁后，先用 `list_devices` 确认实际门锁和实体 ID，再说明具体门锁及开锁风险，并等待本轮对话中针对同一门锁、同一动作的明确确认。确认前不得调用开锁动作；确认后才可设置 `confirmed: true`。旧会话确认、含糊答复或对其他动作的确认均无效。
4. **执行一次**：调用 `control_device`，传入准确的 `device_id`、`action` 和必要参数。不要因等待或回执迟到就盲目重复动作；需要时沿用同一幂等键。
5. **验证结果**：工具返回成功后，再调用 `get_state` 读取实际状态。只有读回状态符合目标，才报告成功。若执行失败或状态不符，明确报告失败/未验证，不要说“已经完成”。

## 目标缺失时的固定追问

用户只说“关一下吧”“开一下”等短句，未说明设备或房间时，不猜设备、不调用工具，直接询问：“你想关掉/打开哪个设备？请告诉我房间和设备名称。”这是对当前请求的必要回应，不得以 `NO_REPLY` 或空内容结束。

## 自动化与未来触发请求

- “以后……”“每次……就……”等定时、条件触发或自动化请求不是当前控制指令，不得调用 `control_device` 执行未来规则。
- 当前 Agent 没有创建或启用 Home Assistant 自动化的工具。应说明能力边界；如用户希望规划方案，先询问具体房间/设备、触发条件、持续时间、授权范围和停用方式。
- 讨论自动化时不得猜测实体 ID；如需确认设备是否存在，先用 `list_devices`，再根据真实列表向用户追问。不要把自动化规则写入家庭偏好记忆。
- 不论能否执行，都必须向用户给出解释或追问，不得静默返回 `NO_REPLY` 或空内容。

## 回复

- 先报告目标设备、动作和验证后的状态。
- 当前若连接的是项目内置模拟后端，要说明是“Mock HA 模拟结果”，不能说真实家具已被控制。
- 设备不可用、动作不支持或参数越界时，停止执行并说明工具返回的原因。
- 本 Skill 不用于组合场景；回家、睡眠或离家模式请求交给 `scene-control`。
