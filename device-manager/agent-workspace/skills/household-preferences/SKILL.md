# 家庭偏好与记忆管理

本 Skill 通过设备管家插件的家庭记忆工具管理少量结构化偏好。记忆保存在家庭边缘端的本地文件中，不是对话历史、长期知识库或 OpenClaw 的梦境日记。

## 支持范围

- `comfort_temperature_c`：舒适温度（16–30℃），可按房间区分；
- `sleep_time`、`wake_time`：本地时间 `HH:mm`，可按工作日/周末区分。

查询“我平常喜欢多少度/几点睡”时，使用 `get_household_preference`；用户要求查看全部记忆时使用 `list_household_memories`。只把 `status: confirmed` 的记录当作用户偏好。没有记忆时如实说明并询问，不能编造“习惯值”。

## 写入与推测

- 用户明确说“记住”“以后默认”或“长期按这个设置”时，调用 `remember_household_preference`，设置 `user_explicit_request: true`。一次性调温/开灯指令不等于长期记忆授权。
- 从重复事件观察作息前，先取得用户明确同意，再由获准的上游适配器提供结构化事件并调用 `propose_household_memory_candidate`。仅限睡觉/起床观察；输入事件 ID、带时区的 `occurred_at`、家庭 IANA 时区、观察时间和置信度。日期由代码计算、观察时间按 15 分钟归并；至少 3 个不同本地日期且每次置信度达到 0.8，才会出现待确认候选。同一天的重复事件不增加观察次数。不得把普通聊天、图片或推测伪装成结构化来源事件。
- 候选未确认前不能用于设置设备或自动安排日程。先向用户展示具体内容和证据摘要，再等待明确同意，然后调用 `confirm_household_memory_candidate` 并设置 `user_confirmed: true`。
- 用户要求忘记/删除时，先列出并确认目标记录，再使用 `forget_household_memory`。不要用日记、自由文本或原始聊天副本替代结构化存储。

## 隐私与执行安全

- 只存值、范围、来源类型、置信度、事件 ID、确认状态和有效期；不保存原始对话、儿童图像/视频、身份信息、API Key、密码或瞬时设备状态。
- 作息偏好是计划条件，不是执行授权。到达睡觉/起床时间后仍需由明确的定时触发器、当前设备状态和策略检查共同决定是否生成任务；本版本还没有自动定时触发器。
- 记忆文件位于本机应用数据目录，当前 JSON 文件没有应用层加密；不要复制到 Git、云盘或跨设备同步。当前后端为 Mock 时，任何设备动作都必须标注模拟结果。
