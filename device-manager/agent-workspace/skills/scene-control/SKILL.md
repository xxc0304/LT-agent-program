# 家庭场景控制

用户明确要求“回家模式”“睡眠模式”或“离家模式”时使用本 Skill。只允许调用现有场景，不要把自然语言临时拼成未定义的批量设备动作。

## 场景映射

- 回家模式 → 调用只读 `plan_scene`，`scene_id: "home"`。
- 睡眠模式 → 调用只读 `plan_scene`，`scene_id: "sleep"`。
- 离家模式 → 调用只读 `plan_scene`，`scene_id: "away"`；该场景不读取温度偏好。

如果用户意图不明确，先询问；若用户提出的组合不属于上述场景，说明当前没有对应预定义场景，不得冒充已执行。

## 执行和验证

1. `plan_scene` 只返回建议步骤，绝不控制设备。它只读取 `confirmed` 温度偏好；候选、过期或未确认记忆不能进入计划。
2. 仅当设备在线且温控上下限已知、偏好值在范围内时，才把卧室温度写入建议步骤；否则保留场景固定值并说明原因。
3. 先向用户展示完整步骤、温度、是否个性化和 `confirmation_phrase`，明确要求用户在后续单独一条消息中原样发送确认口令。不得在同一轮请求中自行补造或回填口令，也不能仅凭记忆自动控制。
4. 只有收到用户后续消息中的原样口令后，才可调用 `execute_scene_plan`，参数必须使用对应的 `plan_id` 和原样 `confirmation_phrase`。工具会检查口令、十分钟有效期、计划是否过期/已使用，并重新读取偏好和设备条件；Gateway 重启也会使未完成计划失效。任何变化都应重新预览并再次询问。
5. 不得为了执行预览计划而直接调用 `run_scene` 或 `control_device`。`run_scene` 只保留为旧版固定参数接口；不能声称它执行了 `plan_scene` 中的个性化温度。
6. 确认后执行工具会先完整预检涉及设备，再执行并返回逐项状态验证及审计关联 ID。若预检失败，说明没有执行；若只部分成功或任一项目验证失败，逐项列出结果，不能汇报为整体成功。
7. 不要因部分失败而自动重跑整个场景，以免重复执行已成功的动作。先查询当前状态并解释结果，再由用户决定下一步。
8. 项目预定义场景不包含开锁。用户要求开锁时，转交 `device-control` 的单独确认流程。
9. 当前后端为 Mock 时，应明确标注模拟执行结果。

确认口令是工具层的防误触和过期保护，不是独立于 Agent 的强身份认证。真实部署如需抵御模型自行填入口令，应接入 OpenClaw 原生人工审批或独立确认 UI。
